# Set up the current machine as a LocalSingleNode deployment node

1. Start only when the operator explicitly asks to set up **this current PC**, for example “set it up, you are node-demo” in a session on that node. A controller session discussing another PC is not authorization. Reject Windows and WSL. Use the requested node name, otherwise `hostname`.
2. Run `bash Deployment/LocalSingleNode/Scripts/setup-status.sh --node <name> --json`. If the operator supplied an address, append `--expected-address <IPv4>` to status and every next-step command. Compare the native hostname and detected address before presenting any root command. A mismatch stops setup. Only this explicit current-node request permits hostname changes.
3. Follow the returned actor. For `agent`, run its command and then check status again. The `fork` action gives a repository-edit task: follow the fork guide, finish its normal PR/local-gate/exact-head-CI/green-main process, then resume status. Never report a deferred fork or CI check as complete. With no CI capacity, status moves bootstrap, variables and runner ahead of fork customization and CI.
4. For `human`, show `human_message` and `command` verbatim and stop. The operator authenticates and runs the one root command. Never ask for, type, copy or store a password/token. Never run sudo yourself or add sudoers rules for the install user. The bootstrap's deploy account has passwordless sudo and Docker access; both confer root-equivalent power. Optional fork CI capacity explicitly grants the install user Docker group access for local gates; start a fresh group session afterwards.
5. Never edit `/etc` by hand, reclaim a lock, prune volumes or dispatch another target. Keep the recorded CD run ID if watching stops. Inspect/reuse that run; never dispatch again because of a watcher failure.
6. Stop if the same agent step fails twice. Record the step and safe output; fix repository failures through a PR. For runner registration timeout, present the service-status command from the error to the operator.
7. When status reports `none`, report the site URL, initial CD run URL/SHA/digest and `pwsh -NoProfile -File Scripts/Test-DeployedSite.ps1 -Address <detected IPv4> -Port <HTTP port>` for the main-PC agent. The main PC runs this check independently. Recommend a DHCP reservation when one does not exist.

The root command rejects unsupported platforms, missing root/SUDO_USER, identity mismatches and fixture paths before mutation. Re-run the same command after a numbered failure; it preserves existing secrets, registrations and volumes. Repository-owned shared Caddy configuration is reused; foreign configuration requires inspection.
